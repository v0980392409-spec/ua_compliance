# UA Compliance

Ukrainian legal layer for ERPNext / Frappe: official NBU exchange rates, effective-dated legal
parameters with their legal basis, and a signed update channel that never applies anything without a
human approval. Unofficial, community-maintained. Work in progress.

---

## Навіщо

Значення, які задає закон (курс НБУ, мінімальна зарплата, прожитковий мінімум, ставки, календар,
класифікатори), у типовій поставці ERPNext або відсутні, або беруться з випадкових джерел. Приклад,
з якого почався застосунок: штатне джерело курсу змішує котирування вісімнадцяти центробанків, і
18.09.2026 воно давало 44,684 грн за долар замість офіційних 44,6648 НБУ, тоді як бухгалтерський
облік ведеться за офіційним курсом НБУ (НП(С)БО 21).

Застосунок робить із цього окремий шар:

- **курс НБУ** завантажується з першоджерела і лягає у штатний запис курсу — документи й звіти
  працюють без доробок;
- **законодавчий параметр** живе записом із періодом дії та підставою (норма, номер, дата,
  посилання на текст): видно не лише число, а й чим воно задане;
- **оновлення** приходять підписаним пакетом даних: застосунок перевіряє підписи, версію, строк
  придатності та хеші, показує, що саме зміниться, і застосовує **лише після підтвердження людиною**;
- **календар і норма часу** будуються з параметрів, тому закінчення воєнного стану змінює правила
  без правки коду;
- **класифікатори** (КАТОТТГ, ДК 003, КВЕД) доступні лише для читання, виведені з обігу коди
  закриваються датою, а не видаляються.

## Стан

Ранній. Перший зріз — офіційний курс НБУ. Решта за планом: параметри, канал пакетів, календар,
класифікатори.

## Встановлення

Застосунок ставиться монтуванням каталогу в сервіси сайту (без перезбирання образу) або штатним
`bench get-app`. Після встановлення:

1. вимкнути зовнішнього постачальника курсів;
2. заповнити перелік валют і розклад у «Налаштуваннях законодавства»;
3. прогнати `verify-all.py`.

## Оновлення

Оновлюватися слід **лише з підписаного тега**, перевіривши підпис на своєму боці: ні `bench`, ні
збірка образів, ні хмара Frappe підписів не перевіряють. Пакети даних застосунок перевіряє сам:
підписи (не менше двох із трьох ключів, закріплених у коді), монотонна версія, строк придатності,
хеші файлів. У пакеті немає нічого виконуваного — логіка та формати їдуть лише релізом коду.

Релізний маніфест (тег, коміт, версія) підписують двоє з трьох тих самих ключів. Перед оновленням
завантажте з релізу `release-manifest.json` і обидва `.minisig` у порожній каталог і в копії
репозиторію виконайте:

```bash
git fetch --tags && python3 tools/release_manifest.py verify v0.1.0 <каталог>
```

Канал роздачі пакетів — релізи окремого репозиторію даних; його адреса задається в
«Налаштуваннях законодавства» (поле «Канал роздачі»). Без адреси пакети приймаються лише файлом.

Так зроблено свідомо: у 2017 році через сервер оновлень українського бухгалтерського ПЗ пройшла
атака NotPetya, і клієнти встановлювали все, що приходило.

## Подивитися в роботі

Демонстраційні дані (параметри з періодами дії, свята, календар, курс НБУ за два тижні):

```bash
env/bin/python apps/ua_compliance/demo/seed_demo.py <site>
env/bin/python apps/ua_compliance/demo/seed_demo.py <site> --clean
```

## Розробка

Перевірки, які ганяє CI, запускаються локально:

```bash
python3 -m venv .venv && .venv/bin/pip install ruff pytest requests cryptography
.venv/bin/ruff check . && .venv/bin/pytest -q
```

Повна перевірка на живому сайті (створює документи в пісочниці й прибирає за собою):

```bash
env/bin/python apps/ua_compliance/verify-all.py <site>
```
